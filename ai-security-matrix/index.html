How to use this

No single tool covers the grid

Even the broadest platforms are weak on poisoning, memory attacks and output handling. Plan for one runtime AI platform, AI-SPM for discovery, a model scanner if you use open-weight models, and your existing stack for the traditional rows.

Start from what you already own

Prisma AIRS, Cisco AI Defense, Check Point, SentinelOne, Fortinet and Microsoft all sell AI security as an extension of their existing platform. The vendor already in your network or SOC usually wins on integration and cost.

Agentic rows need design controls too

Guardrails reduce the risk of tool misuse but do not replace least privilege, per-agent identities, human approval for irreversible actions, and a kill switch. Treat the agentic rows as architecture requirements first, tooling second.

What this tells you

Risk follows autonomy

Chat tools mostly carry data-leakage and injection risk. Once an AI can call tools, write code or move between systems, identity, privilege and tool-misuse risks dominate. Raise control levels as you move right across the table.

Coding agents are underestimated

They read untrusted repos and issues, hold developer credentials, install packages and run commands. They score high on more rows than any chat use case. Sandbox them and scope their tokens.

Industrial AI changes the stakes

Where AI influences plant control or robots, poisoning, adversarial inputs and bad outputs become safety issues, not only data issues. Keep a human or a hard limit between the model and any physical setpoint.

Use it to set control tiers

Map each new AI project to a column at intake. The high cells in that column give the minimum controls and the tests to run before go-live, which fits a Prove → Scale → Standardize gate review.
